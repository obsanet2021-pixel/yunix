## 📋 Core MCP Server Files

### Main Entry Point
**Path:** `yunix-mcp-server/src/index.ts`
- Server startup and configuration
- Loads dotenv at the top (line 1)
- Supports both stdio and HTTP transports
- Express server for HTTP mode
- MCP server initialization

### Supabase Integration
**Path:** `yunix-mcp-server/src/services/supabase.ts`
- Reads `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`
- Creates Supabase client with service role
- Throws error if credentials missing (THIS IS WHERE YOUR ERROR CAME FROM)
- Filters queries by YUNIX_USER_ID (personal mode)
- Wraps queries with error handling

### Available Tools
**Path:** `yunix-mcp-server/src/tools/`
- `trades.ts` - Trade CRUD operations
- `analytics.ts` - Performance metrics
- `prop-firms.ts` - Account management
- `account-cycles.ts` - Cycle tracking
- `certificates.ts` - Certificate tracking

## 🔑 Key Credentials Locations

**Supabase credentials are read from:**
1. Environment variable `SUPABASE_URL`
2. Environment variable `SUPABASE_SERVICE_ROLE_KEY`
3. Environment variable `YUNIX_USER_ID`

**These are loaded from:**
- `yunix-mcp-server/.env` (local file, not committed)
- Or passed directly as environment variables (deployment)

**Template reference in:**
- `yunix-mcp-server/.env.example` (tracked in git, placeholders only)

---

## 🚨 If Credentials Get Exposed

1. **Immediately rotate** the exposed key in Supabase Dashboard
2. Update local `.env` files with new credentials
3. Commit the rotation (with updated `.env.example` if needed)
4. Push to GitHub
5. Old key is now worthless (rotated)
6. Optional: Use `git filter-repo` to scrub history
